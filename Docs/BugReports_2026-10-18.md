## Root causes found (one fix each, covering several reports)

1. **No network identity for PCG instances.** PCG partition actors and their instanced-mesh components are spawned at runtime under names that
   differ per machine (two processes on one machine too), and instance indices shift as instances are removed. A joiner's RPC that carried the
   component pointer arrived on the host as null ("Unable to resolve default guid from client: ObjectName: PCGPartitionActor_2147442263", 56 lines in
   three host reports). Fix: `FMOInstanceRef` (MOInstanceRef.h: static mesh + world location, resolved by each machine against its own copy, the way
   the removal ledger already matched instances), used by every client-to-server instance request.
2. **Gameplay owned by the UI on whichever machine clicked.** The harvest (KeepOnHarvest menu -> UMOHarvestProgressWidget's UI timer ->
   UMOHarvestSubsystem) and the inspection (UMOInspectionProgressWidget's UI timer -> UMOKnowledgeComponent::InspectItem) ran on the joiner's own copy
   of the pawn: its inventory refused the yields ("Inventory Full!"), and everything it learned lived only in its copy, never on the host, never
   saved. Fix: both are server actions timed on the pawn (`FMOHarvestActions`, `FMOInspectionActions`, `UMOTimedActionComponent`: the simulation owns
   the wait), asked for through `AMOPlayerController::ServerBeginHarvest` / `ServerInspectItem`; the result comes back by client RPC.
3. **The host's worked-ground zones never reached a joiner.** Every machine sweeps the decorative foliage out of terraformed ground on its own PCG
   copy, but the zone list existed only on the host. Fix: AMOGameState replicates it (`FMOReplicatedTerrainZoneArray`, MOTerrainModificationTypes.h).
4. **Notifications the server raised for a joiner were never shown.** UMONotificationComponent on the server's copy of a joiner's controller queued
   them and stopped (no local screen). Fix: it forwards to the owning player (ClientShowNotification / ClientShowSkillPopup).
