## MEDIUM IMPACT Findings (35+ total)

Key patterns identified:
- **CommonUI adoption**: Tab lists, activatable widgets, input routing across 6+ menus
- **Gameplay Tags**: Tool types, item types, conditions, knowledge IDs
- **Data Registry**: Item definitions, recipe definitions, quest definitions
- **GAS**: Modifiers, effects, stamina costs, crafting costs
- **EQS**: Flee locations, job locations, resource queries
- **FTimerManager**: Tick-based operations should use timer-based patterns

## LOW IMPACT Findings (40+ total)

## Systems NOT Needing Changes (Correctly Custom)

These systems are intentionally custom and should NOT be refactored:

| System | Reason |
|--------|--------|
| **Persistence/Identity** | Custom GUID required - native `ActorGuid` only works in dev builds |
| **Medical simulation** | GAS is overkill for physiological simulation; DataTable approach superior |
| **Building system** | Well-architected; no native alternatives for weighted build parts |
| **FastArraySerializer usage** | Already using correct UE5.7 pattern |
| **TSoftObjectPtr usage** | Already using correct UE5.7 pattern |

---

## Recommended Priority Order

1. **CommonUI full adoption** (UI Controllers) - HIGH impact, reduces ~3000 LOC
2. **EQS for AI queries** (Survivor/Creature AI) - HIGH impact on performance
3. **Gameplay Tags migration** (Medical conditions, Equipment slots, Quest types) - HIGH extensibility
4. **Smart Objects** (Interaction, Harvesting) - HIGH, modern UE pattern
5. **Data Registry** (Items, Recipes, Quests) - MEDIUM, async loading benefits
6. **Enhanced Input Triggers** (Character hustle) - Quick win
7. **PCG distance culling** (Spawning) - Remove custom node
8. **StateTree evaluation** (AI systems) - DEFER to future refactor
9. **GAS evaluation** (Combat) - DEFER, current system well-integrated with medical
