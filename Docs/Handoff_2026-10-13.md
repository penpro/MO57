## Regressions and defects (fix first)
1. **fix: new-game load got ~16 s slower.** In the cooked build READY now arrives after 45.7 s; the Vegetation stage runs from +13.8 s to +45.5 s, which is its 32 s hard cap. Before this pass it was ~29 s.
   - Likely cause: `mo.Readiness.NearInstanceMin` = 200 counts non-far instances within 60 m. Ground items were most of those at the coast spawn, and they are now x10-20 fewer.
   - Second suspect: the canopy tier keeps PCG busy longer.
   - To confirm: log the near count at the cap. Then lower the minimum, or count by "near tiers generated" instead of an instance count. Re-measure in the packaged build.
2. **fix: the item thinning roughly doubled native black-locust clumps.** I wrote that `RandomChoice_3`'s Discarded output is a dead end. It is not:
   - The real path is `CopyPoints_1` (fed by `CreatePointsGrid_1`) -> `TransformPoints_6` -> `VoxelProjection_1` -> `StaticMeshSpawner_3` (SM_wdvhberja_VarA/B/C).
   - My downstream trace stopped at depth 9; the upstream trace of `StaticMeshSpawner_3` shows the link.
   - Raising the Discarded share from 0.5 to 0.95 grows that branch ~1.9x, and each point copies a whole grid of bushes.
   - Fix: put `RandomChoice_3` back to 0.5. Thin the items with a NEW RandomChoice (ratio 0.1, Discarded unconnected) between `RandomChoice_3.Chosen` and `RandomChoice_1`. Use `add_node_of_type` + `add_edge_to` + the graph's remove-edge; do not delete nodes from Python. Update `thin_item_clutter.py` to match.
3. **fix: far tiers leave bald circles where the player started or teleported.** `MOPCGBiomeSpawnerSettings` skips points within `MinDistanceFromViewerCm` of the viewer at generation time. That is 1.5 km for stand-ins and 2.2 km for canopy.
   - Cells stay generated while the player walks away, so the area around the start point never gets far instances.
   - Walk 3 km off and look back: real trees end at 1.5 km, stand-ins and canopy were never planted there, and the result is a hole of up to ~2 km radius.
   - `InstanceMinDrawDistance` already hides near instances per frame, so the generation-time skip buys nothing (~5 k extra hidden instances).
   - Fix: drop the generation-time skip for the far tiers and keep the descriptor's `InstanceMinDrawDistance`. Check by walking 3-4 km from spawn and looking back.
4. **fix (honesty): the perf numbers in this pass are not comparable.** The same configuration measured anywhere from 64 to 102 fps across runs, depending on stale far cells, weather and whether the editor was open.
   - The "78.9 -> 101.9 fps" in `b4846421`'s message and in `Docs/Overnight_Polish_2026-10-12.md` overstates the result.
   - Re-measure in the packaged build with `MO.Perf.Tour` from a fresh boot per configuration: field trees off vs on, canopy on vs off, items thinned vs not. Then correct the doc.

## Notes
- **note: generator v7 has no save compatibility check.** `GeneratorVersion` is only logged and hashed. Old saves regenerate with the v7 caves, so caves under high ground vanish under existing builds. Acceptable pre-alpha; say it in release notes.
- **note: snow is one global altitude line** (`SnowLineCm` 1250 m) on the terrain only.
  - It ignores climate, latitude and season (the generator has a temperature field).
  - Rocks and trees under it do not get snow.
  - A Material Parameter Collection driven by the weather / season system is the next step.
- **note: the far tint is per surface, not per biome.** Forest floors (MuddyLeaves, ForestLitter, JungleFloor) go to canopy green. A new surface needs a row in `SURFACES` in `upgrade_terrain_material.py`, or it gets no tint.
- **note: material scripting rules.**
  - `upgrade_terrain_material.py` builds the M_QuixelBase graph once, then only updates shader code and parameters.
  - For a structural change: revert `M_QuixelBase.uasset` from git, then run it on the pristine graph.
  - Never call `MaterialEditingLibrary.delete_material_expression` or `delete_all_material_expressions`: both asserted `!IsRooted` and killed the editor.
  - `unreal.StaticMeshDescription` from Python also crashes; import OBJ instead.
- **note: the screenshot tools are broken.** `Tools/biome_tour.py` and `Tools/ui_shoot.py` (window capture) now return a 320x180 game image inside a 1920x1080 frame, because the instance window size changed. Use `Tools/biome_eye.py`, `Tools/look_sheet.py` or `Tools/steam_scout.py` (HighResShot).
- **note: the Steam art Wes rejected is still in the repo** (`SteamArt/`, ~15 MB LFS, pushed). Delete it only if he says so.

## Efficiency (what cost the most time)
- **Six editor restarts at ~4 min each**, for C++ builds and two crashes.
  - Batch C++ edits.
  - Content edits do not need an editor restart.
  - The `ui` instance runs fine next to the editor for VISUAL checks, but never for perf: they share the GPU.
- **After a crash the bridge never comes up**, because the editor sits on the package-restore dialog. Run `ue.py editor stop`, move `Saved/Autosaves` aside, then start again.
- **Python API traps:**
  - Struct array elements read from `get_editor_property` are copies. Rebuild the structs and set the whole array.
  - `MaterialExpressionSetMaterialAttributes.inputs` is protected. Use Break/Make MaterialAttributes.
  - Bash heredocs containing `'''` break. Write patch scripts with the Write tool.
- **Sky:** `MO.Clock.SetTime` only moves the sky forward in game time. Use `MO.Weather.Director 0` + `MO.Weather.SetPreset Clear_Skies` for stable shots, and `r.VolumetricRenderTarget 0` for 4K clouds.
- **Find what an artefact is made of** with `MO.PCG.MeshSurvey`, `MO.PCG.HideMesh` and `MO.PCG.HideTag` before guessing. That is how the native Field_05 trees (90 k, biome-blind) turned out to be the "speckled far forest", after an hour spent blaming the biome tiers.
